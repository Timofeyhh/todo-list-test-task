# Список задач

Небольшое веб-приложение «Список задач» (To‑Do List) на React и TypeScript — тестовое задание.
Задачи можно добавлять, отмечать выполненными и удалять; всё сохраняется в `localStorage`
и восстанавливается после перезагрузки страницы. Бэкенд не нужен.

**Рабочая версия:** https://timofeyhh.github.io/todo-list-test-task/

## Возможности

Обязательные:

- добавление задачи по Enter или кнопке «Добавить»: пробелы по краям обрезаются,
  пустую задачу добавить нельзя (показывается подсказка), после добавления поле очищается
  и остаётся в фокусе;
- отметка задачи выполненной и возврат в активные (текст зачёркивается и приглушается,
  чекбокс становится чёрным);
- удаление задачи кнопкой «×» у каждой строки, без подтверждения;
- сохранение после каждого изменения и восстановление после перезагрузки.

Дополнительные:

- две категории — «Срочно» и «Не срочно»: выбираются при добавлении (по умолчанию «Не срочно»),
  список разделён на группы, срочные сверху; категорию уже созданной задачи можно сменить
  стрелкой в её строке (↑ — сделать срочной, ↓ — сделать не срочной);
- фильтры «Все / Активные / Выполненные» со счётчиками;
- количество оставшихся задач с правильными склонениями («Осталась 1 задача», «Осталось 5 задач»);
- кнопка «Удалить выполненные» — показывается, только когда есть выполненные задачи;
- счётчики активных и выполненных задач в информационной колонке, у каждого — разбивка на
  «Срочно» и «Не срочно»;
- пустые состояния для списка и для каждого фильтра;
- адаптивная вёрстка: две колонки на десктопе, одна — на экранах до 720 px.

Доступность:

- семантическая разметка (`main`, `form`, `section`, заголовки `h1/h2`, `ul/li`, `footer`), язык страницы — `ru`;
- категория выбирается обычными радиокнопками в группе с подписью (работают стрелки), каждая
  группа задач — список с заголовком;
- у поля ввода есть связанный `label`; ошибка пустого ввода связана с полем через
  `aria-describedby` и `aria-invalid`;
- статус задачи меняется нативным чекбоксом, подписанным текстом задачи; вся строка задачи —
  зона нажатия;
- у кнопок с иконками доступные имена: «Удалить задачу «…»», «Сделать задачу «…» срочной»;
  после смены категории фокус остаётся на кнопке перенесённой задачи;
- фильтры — кнопки с `aria-pressed` в группе с подписью;
- добавление, выполнение и удаление объявляются скринридеру через `role="status"` (`aria-live="polite"`);
- всё работает с клавиатуры, фокус виден (`:focus-visible`); если элемент в фокусе исчезает
  (удаление, скрытие фильтром), фокус переходит на список, а не теряется;
- контраст текста и границ элементов управления соответствует WCAG AA;
- все интерактивные элементы не меньше 44 px;
- `prefers-reduced-motion` отключает короткие переходы при наведении, фокусе и отметке задачи;
- в режиме высокой контрастности Windows зачёркивание, чекбокс и активный фильтр остаются видимыми.

## Стек

- [React 19](https://react.dev/) + [TypeScript 6](https://www.typescriptlang.org/) (строгий режим)
- [Vite 8](https://vite.dev/) — dev-сервер и сборка
- обычный CSS с CSS-переменными, без UI-библиотек
- шрифты [Onest](https://fontsource.org/fonts/onest) (основной текст) и
  [IBM Plex Mono](https://fontsource.org/fonts/ibm-plex-mono) (мелкие подписи) из пакетов
  `@fontsource-variable/onest` и `@fontsource/ibm-plex-mono` — файлы шрифтов входят в сборку,
  внешних запросов нет
- `localStorage` для хранения
- [ESLint 10](https://eslint.org/) с `typescript-eslint`, `react-hooks`, `react-refresh`
- [Vitest](https://vitest.dev/) + [Testing Library](https://testing-library.com/) + jsdom — тесты
- GitHub Actions — проверки и публикация на GitHub Pages

Зависимости в рантайме: `react`, `react-dom` и два пакета `@fontsource` (только файлы шрифтов).

## Структура

```text
src/
├── App.tsx                 # состояние фильтра, производные значения, сообщения для скринридера
├── components/
│   ├── TodoForm.tsx        # поле ввода, кнопка добавления, выбор категории, валидация
│   ├── StatsItem.tsx       # счётчик в информационной колонке с разбивкой по категориям
│   ├── TodoFilters.tsx     # Все / Активные / Выполненные
│   ├── TodoList.tsx        # группы по категориям или пустое состояние
│   └── TodoItem.tsx        # чекбокс, текст, кнопки смены категории и удаления
├── hooks/useTodos.ts       # состояние задач и синхронизация с localStorage
├── lib/
│   ├── todoStorage.ts      # безопасное чтение/запись и проверка структуры данных
│   └── format.ts           # склонения в счётчике задач
├── types.ts                # типы Todo, TodoFilter и список категорий
├── index.css               # все стили
└── *.test.ts(x)            # тесты рядом с кодом
```

## Локальный запуск

Нужен Node.js 22.22+ или 24.15+ (LTS) и npm.

```bash
npm install
npm run dev
```

Приложение откроется по адресу, который выведет Vite (обычно http://localhost:5173).

## Сборка

```bash
npm run build     # проверка типов (tsc -b) и production-сборка в dist/
npm run preview   # локальный просмотр собранной версии
npm run lint      # ESLint
```

Сборка использует относительные пути (`base: './'`), поэтому `dist/` работает и в корне домена,
и в подпапке, например на GitHub Pages.

## Тесты

```bash
npm test             # однократный запуск
npm run test:watch   # режим наблюдения
```

Что проверяется (36 тестов):

- добавление по Enter и по кнопке, обрезка пробелов, очистка поля и фокус после добавления;
- категории: «Не срочно» по умолчанию, срочные задачи попадают в свою группу и идут первыми,
  выбранная категория запоминается для следующей задачи, группы восстанавливаются после перезагрузки;
- смена категории у существующей задачи (фокус остаётся на её кнопке) и разбивка счётчиков
  по категориям;
- задачи, сохранённые до появления категорий, читаются как «Не срочно»; неизвестная категория
  считается повреждением данных;
- запрет пустой задачи и задачи из одних пробелов;
- отметка выполненной и возврат в активные, с сохранением в `localStorage`;
- удаление;
- фильтры и «Удалить выполненные»;
- сохранение после повторного монтирования приложения (аналог перезагрузки страницы)
  и восстановление заранее записанных данных;
- повреждённый `localStorage` (невалидный JSON, не массив, элементы неверной структуры) —
  приложение стартует с пустым списком и продолжает работать;
- недоступный `localStorage` и переполнение квоты не приводят к ошибкам;
- склонения в счётчике оставшихся задач.

## Хранение данных

Задачи хранятся в `localStorage` под ключом `todo-list:v1` в виде JSON-массива:

```json
[
  {
    "id": "0b6f1c2e-6a8e-4d39-9a57-2f3b1f6b5a10",
    "text": "Купить продукты",
    "completed": false,
    "category": "normal",
    "createdAt": 1763022000000
  }
]
```

- `id` — `crypto.randomUUID()` (на страницах без HTTPS — запасной генератор);
- `category` — `"urgent"` («Срочно») или `"normal"` («Не срочно»);
- `createdAt` — время создания в миллисекундах; хранится в данных, но в интерфейсе не показывается.

Версия в ключе нужна, чтобы при несовместимом изменении формата данных можно было перейти на новый
ключ и не читать старые данные как новые. Поле `category` добавлено позже совместимо: у задач,
сохранённых без него, категория считается «Не срочно», поэтому ключ остался `todo-list:v1`.

Данные сохраняются после каждого изменения (`useEffect` в `useTodos`) и читаются один раз
при старте (ленивый инициализатор `useState`). Чтение обёрнуто в `try/catch`, а результат
проверяется: это должен быть массив, и у каждого элемента должны быть непустые `id` и `text`,
логический `completed`, числовой `createdAt` и (если есть) известная `category`. Если данных нет, JSON не парсится или структура
не совпадает, приложение стартует с пустым списком и пишет предупреждение в консоль;
некорректное значение затем перезаписывается корректным. Ошибки записи (например, переполнение
квоты) тоже не ломают интерфейс.

Ограничения: данные живут только в этом браузере и профиле, между устройствами не синхронизируются;
изменения в другой вкладке подхватятся только после перезагрузки страницы. Длина задачи
ограничена 500 символами.

## Использование AI

При работе использовался **Claude** (Anthropic) в приложении Claude Code:

- для первоначального планирования — структура компонентов, формат данных, план тестов;
- для генерации части реализации — компоненты, стили, тесты, конфигурация;
- для проверки граничных случаев — повреждённый или недоступный `localStorage`, ввод из одних
  пробелов, длинный текст без пробелов, потеря фокуса после удаления, вёрстка на ширине 320 px,
  контраст текста и границ, совместимость со старыми данными без категорий.

Итоговая структура, функциональность и код проверены разработчиком: линтер, тесты и сборка
проходят, приложение проверено вручную на десктопной и мобильной ширине.
